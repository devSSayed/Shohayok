# Shohayok

Single Next.js 16.4 App Router app (`src/` dir). Not a monorepo. No tests, no CI, no Prettier.

## Commands

- `npm run dev` — dev server on localhost:3000 (Turbopack)
- `npm run lint` — ESLint 9 flat config (`eslint.config.mjs`)
- There is **no typecheck script** — run `npx tsc --noEmit` to verify types
- Verify with `npm run lint && npx tsc --noEmit`; there is nothing to test

## Toolchain quirks

- `next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `reactCompiler` (React Compiler via `babel-plugin-react-compiler`). See the block above and `node_modules/next/dist/docs/` before using Next APIs — this Next version differs from older training data.
- Route props use generated types, e.g. `LayoutProps<"/">` in `src/app/layout.tsx` — never hand-write them.
- Tailwind CSS v4, CSS-first config in `src/app/globals.css` (`@theme`, no `tailwind.config.*`). CSS is compiled through the `@tailwindcss/turbopack` loader rule in `next.config.ts` — don't add a Tailwind config file or PostCSS setup.
- shadcn is set to style **`base-nova`** (`components.json`): UI primitives come from `@base-ui/react`, **not Radix**. Add components with `npx shadcn add <name>` so the right variants are generated.
- `cn` is the npm `cn` package — `src/lib/utils.ts` just re-exports it; there is no local `clsx`/`tailwind-merge` implementation. New code should import from `@/lib/utils` (the shadcn alias); existing generated `ui/` files import `"cn"` directly.
- No `"use client"` anywhere yet — everything is a server component. Add it only when a component truly needs client interactivity.

## Layout

- Path alias: `@/*` → `./src/*` (also configured in `components.json` for shadcn)
- `src/app` — pages and root layout; `src/components` — `NavCompo/`, `ui/` (shadcn), `banner.tsx`; `src/assets` — images
